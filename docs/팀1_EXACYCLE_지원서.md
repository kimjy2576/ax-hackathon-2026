## SECTION 3. 문제정의

### 현재 업무 방식 및 Pain Point

사내에서 냉동사이클·히트펌프를 채용한 제품은 냉장고, 건조기, 스타일러, 정수기 등 전 제품군으로 확대되어 왔으며, 식기세척기 역시 선행 단계에서 히트펌프 도입을 검토 중일 만큼 적용 범위는 현재진행형으로 넓어지고 있다. 그러나 HS사업부 내에서 사이클을 전문으로 다루는 조직은 리빙솔루션Cycle개발Project가 유일하며, 이마저 양산 개발 지원에 집중되어 있어 Cycle 기술 자체의 선행연구를 수행하는 조직은 부재하다.

이 공백은 현재 두 가지 형태의 비효율로 나타나고 있다. 첫째, 각 제품 개발팀이 사이클 설계·해석 업무를 전문 조직 없이 자체 소화하고 있다. 비전문 인력의 시행착오형 검토가 제품팀마다 반복되고, 유사한 설계 검토가 제품군 간에 중복 수행된다. 검토 1건당 평균 40시간(총 인적공수)의 작업이 제품군당 연간 12건 반복되어, 현재 사이클 채용 4개 제품군(냉장고·건조기·스타일러·정수기) 기준 연 1,920시간이며, 히트펌프 도입을 검토 중인 식기세척기까지 포함하면 연 약 2,400시간 규모로 확대된다. 탐색 범위 역시 "담당자가 돌려볼 수 있는 만큼"으로 제한되어 설계공간의 상당 영역이 미탐색 상태로 검토가 종결된다. 둘째, 사이클 선행연구는 현재 각 제품 선행연구팀이 본업과 병행하는 겸무 형태로 수행되고 있다. 겸무 구조에서는 제품 개발 지원이라는 본업에 항상 우선순위가 밀려 연구가 착수와 중단을 반복하고, 담당자가 바뀔 때마다 축적이 초기화되어, 시간은 투입되지만 진전은 없는 상태가 지속되고 있다. 응용 냉동사이클 적용 가능성 검토, 대체냉매 탐색, 신기술 연구개발과 같은 핵심 선행과제들이 수년째 실질적 산출 없이 이월되는 이유다.

근본 원인은 사람으로 이 공백을 메울 수 없다는 데 있다. 사이클 전문가는 채용 풀 자체가 극히 좁고 육성에 10년 단위가 소요되어, 조직 신설로는 해소가 불가능한 구조적 문제다.

### 해당 문제의 중요성

경쟁력 축: 냉매 규제(EU F-gas 개정, GWP 규제 강화)와 에너지 규제(에너지등급, EU ErP, 미국 DOE)는 사이클 기술력이 곧 제품의 시장 진입 자격이 되는 방향으로 강화되고 있다. 선행연구 공백은 규제 대응 실기와 직결되며, 히트펌프 효율 1~2% 차이가 에너지등급과 판가·판매량을 좌우한다.

시간·비용 축: 현재 4개 제품 선행연구팀이 사이클 선행연구 겸무에 연간 약 3,840시간(팀당 약 960시간, 0.5명 상당의 겸무 투입)을 들이고 있으나 실질 산출로 이어지지 못하는 이중 낭비가 발생하고 있으며, 여기에 제품팀별 중복·시행착오 검토 연 1,920~2,400시간(40시간 × 12건 × 4~5개 제품군)이 더해진다. 합산하면 연 5,760~6,240시간이 산출 없는 구조에 투입되고 있는 셈으로, 1인 연간 실가용 연구시간(약 1,800~1,900시간) 기준 약 3.3명 상당의 업무량이다. 이는 감축 가능 인력이 아니라, 여러 조직에 분산되어 중복·대기·중단 형태로 소모되는 FTE 환산 업무량을 뜻한다. 가상 선행연구팀은 소수 전문가의 지식과 검증된 해석 도구를 에이전트로 복제·확장함으로써, 채용·육성으로는 불가능한 이 공백을 메우는 유일하게 현실적인 수단이다.


## SECTION 4. AI서비스 구성계획

**서비스가 담당하는 업무 유형(4종)**: ① 제품 설계 검토(요구사양 → 설계안), ② 응용 냉동사이클 적용 가능성 검토(다단·캐스케이드·이젝터 등 구성 대안 평가), ③ 대체냉매 탐색(규제 대응 냉매 후보 스크리닝·평가), ④ 신기술 연구개발. 네 유형은 분기-수렴 구조로 처리된다: PM 에이전트가 과제 유형을 분류하면 설계 에이전트가 유형별 탐색 전략으로 분기하고, 이후 해석 → 검증 → 보고의 공통 백본으로 수렴한다.

### AS-IS 워크플로우 (7단계)

1. 과제 접수 및 해석 조건 번역 — 제품팀 요구사양 또는 선행과제(응용사이클·대체냉매·신기술 연구개발)를 담당자가 해석 가능한 조건으로 정의
2. 설계변수·범위 선정 — 담당자 경험에 기반해 탐색할 변수와 범위를 수동 결정
3. 해석 케이스 셋업 — 케이스별 입력 파일을 수작업 작성 (검토 1건당 수십~수백 케이스)
4. 1D 해석 실행 및 진행 관리 — 실행, 수렴 확인, 실패 케이스 재실행을 수동 관리
5. 결과 후처리 — 성능맵·트레이드오프 정리, 그래프 작성
6. 물리 타당성 검토 — 시니어 리뷰로 이상 결과 스크리닝 (시니어 가용성에 의존)
7. 검토 보고서 작성 및 공유

### TO-BE 워크플로우 (5단계, 4개 에이전트)

1. **[PM 에이전트]** 요구사양 입력 → 설계 브리프 자동 생성 → **사람 승인 게이트** — *대체: AS-IS 1*
2. **[설계 에이전트]** 설계공간 정의 — 과거 검토 사례·설계 지식 기반으로 변수·범위·제약을 자동 제안, 민감도 분석으로 핵심 변수 선별 — *대체: AS-IS 2*
3. **[해석 에이전트]** 케이스 자동 생성 → 1D 해석 엔진(MCP 도구) 일괄 실행 → 수렴·실패 자동 관리 → 후처리 자동화 — *대체: AS-IS 3, 4, 5 (3단계가 1단계로 통합)*
4. **[검증 에이전트]** 물리 타당성 검증 — 에너지 밸런스·물성 범위·경향성 검사, 기준 위반 시 해석 에이전트로 **반려**(재해석 지시), 통과 결과만 다음 단계로 — *대체: AS-IS 6*
5. **[보고 에이전트]** 파레토 프론트·추천 설계안·검토 보고서 초안 생성 → **사람 최종 검토 게이트** — *대체: AS-IS 7*

### 서비스 상세 설명

화면 구성: 웹 대시보드 단일 화면. ① 좌측 사양 입력 패널(자연어+구조화 폼 병행), ② 중앙 에이전트 협업 로그(어느 에이전트가 무엇을 수행·위임·반려했는지 실시간 표시 — 가상팀의 협업 과정 자체가 가시화됨), ③ 우측 결과 패널(설계공간 히트맵, 파레토 프론트 인터랙티브 차트, 보고서 미리보기·다운로드).

Agent 간 판단 기준: 검증 에이전트가 품질 게이트를 전담한다. 에너지 밸런스 오차 임계값 초과, 냉매 물성 유효범위 이탈, 파라미터 대비 성능 경향 역전 등이 감지되면 해당 케이스를 해석 에이전트로 반려하고 재해석 사유를 명시한다. 보고 에이전트는 검증 통과 결과만 사용하며, 사람의 개입은 시작(브리프 승인)과 끝(보고서 확정) 두 게이트로 한정해 자율성과 통제를 양립시킨다.

업무 유형별 동작: 파이프라인은 동일하되 설계 에이전트가 정의하는 탐색공간이 과제 유형에 따라 달라진다. 설계 검토에서는 설계변수 공간(열교환기 사양·압축기 용량·운전 조건 등)을, 대체냉매 탐색에서는 냉매 후보군 공간(물성 DB 기반 1차 스크리닝 후 사이클 성능·GWP·가연성·글라이드를 축으로 한 다목적 평가)을, 응용 냉동사이클 검토에서는 사이클 구성 공간(단일단 대비 다단·캐스케이드·이젝터 등 구성 대안의 성능·복잡도 비교)을, 신기술 연구개발에서는 기술 조사와 모델 반영을 통한 적용 효과 정량화 및 연구 시나리오 도출을 수행한다. 산출물도 유형에 맞춰 설계안, 냉매 후보 순위표, 구성별 비교표, 연구개발 보고서로 달라진다.

예외 처리: (a) 1D 모델 적용 범위 밖 사양(미지원 냉매·구성) 입력 시 PM 에이전트가 한계를 명시하고 부분 수행 범위를 제안한 뒤 사람에게 에스컬레이션. (b) 해석 미수렴 반복 시 해석 에이전트가 초기값·스텝 조정 후 재시도, 한계 도달 시 해당 케이스를 결측 처리하고 검증 에이전트에 보고. (c) 요구사양 간 상충(달성 불가 조합) 감지 시 탐색 중단이 아니라 "달성 가능 경계"를 역제시.

### 구현 기술 스택

멀티에이전트 오케스트레이션은 LangGraph로 구현하며, 1D 해석 엔진·물성 DB는 MCP 도구로 표준화해 연동한다. 지식 자산(과거 검토 사례·설계 지식)은 임베딩 기반 RAG로 서빙한다. LLM은 사내 보안 요건에 따라 사내 승인 모델 또는 로컬 구동(Ollama)을 선택할 수 있도록 설계해 데이터 반출 없는 사내망 운영을 전제한다. 이 스택 전체(Ollama·RAG·LangGraph·MCP)는 팀이 도메인 특화 에이전트 구축을 통해 이미 실전 검증한 조합으로, 본선 4주 내 실동작 구현의 근거다.

### 본선 4주 구현 계획 (09.10 – 10.08)

1주차: 1D 해석 엔진 MCP 래핑, LangGraph 파이프라인 골격, PM·해석 에이전트 우선 구현. 2주차: 설계(탐색 전략 4종)·검증·보고 에이전트 구현 및 반려 루프 완성. 3주차: 통합 후 실제 파일럿 선행 과제 1건 투입, 대체냉매 탐색 시나리오 병행 구동. 4주차: 성공 기준 3종 측정(전문가 검토 일치율·리드타임·과제 완주), 대시보드 완성도 및 최종 심사 데모 시나리오 확정.

### AI가 반드시 필요한 이유

이 업무 중 반복 실행(케이스 배치 실행, 그래프 생성)은 스크립트 자동화의 영역임을 인정한다. 그러나 자동화만으로는 이 워크플로우가 성립하지 않는다. 첫째, 요구사양은 자연어·비정형으로 접수되며 이를 해석 조건으로 번역하는 일은 도메인 문맥 이해를 요구한다. 둘째, "설계공간의 어디를 탐색할 것인가"는 규칙으로 열거할 수 없는 판단이다. 변수 간 상호작용과 제품별 제약을 고려한 탐색 전략 수립은 문서화되지 않은 암묵지의 영역으로, 규칙 기반 시스템으로 만들면 제품·사양이 바뀔 때마다 규칙이 파산한다. 셋째, 해석 결과의 물리적 타당성 판단(이 경향이 말이 되는가, 어떤 케이스가 의심스러운가)은 수치 임계값만으로 환원되지 않는 추론이다. 넷째, 트레이드오프 해석과 보고서화는 결과를 "설계 의사결정 언어"로 번역하는 작업이다. 즉 RPA가 손을 대체한다면, 본 서비스는 겸무 담당자에게 부재한 전문가의 판단을 대체·보강하는 것이며 이는 LLM 기반 에이전트가 아니면 불가능하다.

## SECTION 5. 활용 Data 및 연동시스템

### 연동 예정 사내 시스템 (선택)

NPDM, RMS, DQMS, TIS, EDMS, QMS, ISS, PLM (접수 화면에 태그로 입력)

### 활용 데이터 종류 및 형태

■ NPDM — 부품·설계 정보(정형): 압축기 사양·성능맵, 열교환기 도면·BOM, EEV·팬·모터 특성 등 요소 컴포넌트 상세 스펙 / 컴포넌트 운전 한계(압축기 운전범위·토출온도 한계), 협력사 사양서, 요소기술 설계 기준 → 설계 에이전트의 탐색 변수 정의와 검증 에이전트의 반려 기준 입력

■ RMS — 연구보고서·기술문서(비정형 → RAG): 건조기·세탁건조기 전 제품군 건조 모듈 Cycle 선행연구 이력 보고서, 냉매 후보군 검토 이력(스크리닝 기준·평가 결과), 설계변수 민감도 검토 자료 → 과제 유형별 탐색 전략의 근거 지식베이스

■ DQMS — 개발 품질 평가(정형·문서): 개발 단계 품질·신뢰성 평가 결과, 선행평가 판정 이력 → 검증 에이전트의 판정 기준 참조

■ TIS — 시험정보(정형): 성능 시험 의뢰·결과 이력, 실측 데이터(열량·소비전력·시계열) → 해석 모델 정합(본선 필수)

■ EDMS — 제품기획 문서(비정형): 제품 요구사양서·기획 사양(성능·용량·에너지등급 목표) → PM 에이전트의 입력 해석·설계 브리프 생성

■ QMS — 품질 이슈(문서·DB): 양산·필드의 과거 Cycle 관련 이슈 사례 → 검증 에이전트의 이상 경향 판정 근거

■ ISS — 개발 이슈(DB): 개발 단계 이슈 등록·조치 이력(개발 이슈 관리 대장) → 이슈 패턴의 지식화(RAG)

■ PLM — 과제 관리(문서): 선행과제 제안서·과제계획서, 설계 리뷰·검토 회의록(채택/기각 사유) → 과제 유형 분류·브리프 템플릿과 설계 결정 이력의 지식화

1D 사이클 해석 엔진(세탁기차세대플랫폼Task 자체 개발)과 입력 포맷 정의서·기준 해석 모델은 팀 보유 자산으로 MCP 도구로 연동하며, 냉매 물성(REFPROP)·GWP 규제 정보는 정식 라이선스와 공개 자료를 활용한다. 본선 필수 데이터(해석 엔진, 컴포넌트 스펙, 정합용 실측 데이터)는 팀 보유 자산과 건조기·세탁건조기 1개 기종 범위의 파일 확보로 충족되어 시스템 접근 승인이 본선 일정의 리스크가 되지 않으며, 상기 시스템과의 직접 연동은 확대 단계의 전환 조건으로 한다.

### 1차 적용 대상 (입력값)

### 확대 가능 대상 및 조건 (입력문)

1차 적용은 건조기·세탁건조기 제품군의 사이클 선행·설계 검토(12명)이며, 냉매량·EEV 개도·팬 RPM·열교환기 사양 변경 등 단위 검토가 월 8건 내외로 상시 발생한다. 이들 단위 검토는 연 12건 규모의 종합 설계 검토(1건당 평균 40시간: 조건 정의 → 케이스 해석 → 데이터 정합 → 보고)로 묶여 수행되며, 기대효과(Section 7)의 산식은 보수적으로 종합 검토 단위(연 12건)를 기준으로 한다. 건조기·세탁건조기는 히트펌프가 가장 적극 채용되는 제품군이고 1D 해석 엔진 보유 조직(세탁기차세대플랫폼Task)과의 정합이 가장 높은 진입점이다.

1단계 — HS사업부 사이클 채용 전 제품군(냉장고·스타일러·정수기, 히트펌프 도입 검토 중인 식기세척기 포함 / 검토 인원 25명 = 제품군당 선행·설계 평균 5명 × 5개): 1차 적용에서 ① 산출물의 전문가 검토 일치율 90% 이상, ② 검토 리드타임 50% 이상 단축, ③ 파일럿 선행 과제 1건 완주가 입증되고, 제품별 1D 모델 등록 체계가 구축되면 확대한다. 파이프라인은 동일하며 제품별 모델 등록만 추가된다.

2단계 — ES사업부 공조 전 제품군(AI DC 칠러, 상업용 칠러, RAC·CAC, Multi V, 제습기 / 설계·해석 인원 약 80명): 사이클이 곧 제품의 본질인 사업부로 설계 검토·해석 수요가 사내 최대다. 조건은 ES 보유 해석 도구의 MCP 인터페이스 연동이다 — 에이전트 골격(과제 번역 → 탐색 → 해석 → 검증 → 보고)은 특정 해석 엔진에 종속되지 않으므로 도구 연동만으로 이식된다. 특히 AI DC 칠러는 데이터센터 수요 급증으로 설계 검토가 가장 빠르게 반복되는 영역이다.

3단계 — 전사 시뮬레이션 기반 R&D 검토 표준: 열교환기 단품 해석, 성능 시험 조건 설계 등 인접 1D/저차원 해석 업무까지, 사내 AI 플랫폼 보안·거버넌스 승인과 도구 등록 절차 표준화를 조건으로 확대한다.

단계별 누적 잠재 사용자: 12명 → 25명 → 105명.

### 생산성 향상 기여 근거

업무 단위는 "사이클 설계·해석 검토 1건"이다. AS-IS 40시간은 담당자 1인이 조건 정의(4h), 데이터 준비·모델 입력(8h), 케이스 구성·해석 반복(12h), 실험 데이터 정합(8h), 전문가 리뷰(4h), 보고서 작성(4h)에 투입하는 총 공수로, Section 3의 수치와 동일하다. TO-BE 4시간은 사람 개입이 남는 두 게이트(설계 브리프 승인, 최종 보고 검토)와 중간 확인에 해당한다. 연간 발생횟수 60건은 HS사업부 사이클 채용 5개 제품군 × 제품군당 연 12건으로 Section 3의 발생 빈도와 동일 기준이며, 1차 적용(건조기·세탁건조기)만 보면 연 12건이다. 투입인원 1명은 AS-IS/TO-BE를 1인 기준 시간으로 정의해 이중계상을 배제한 값이다. 발생 빈도를 단위 검토 항목(냉매량·EEV·열교환기 사양 등) 기준으로 세면 제품군당 연 96건(월 8건)에 달하나, 산식은 40시간 단위의 종합 검토 건수로 보수 집계했다.

본 산식에 포함하지 않은 절감 상방이 별도로 존재한다: ① 겸무 형태로 정체된 사이클 선행연구를 가상팀이 대체 수행함에 따른 연 3,840시간(Section 3), ② ES사업부 확대 시 추가 검토 약 연 72건에 해당하는 +2,592시간, ③ 검토 리드타임 단축과 시제·재시험 감소 효과. 이를 합산하면 잠재 절감은 연 8,500시간을 상회하나, 기입값은 Section 3에서 실측 기반으로 방어 가능한 범위(2,160시간)로 보수적으로 한정했다.

### 경영성과 기여 근거 (입력문)
